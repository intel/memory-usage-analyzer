# Introduction

This is the **VM counterpart of [`tests/redis`](../redis/README.md)**. It runs Redis servers driven by `memtier_benchmark` across paired KVM virtual machines to estimate the Redis workload's memory footprint and measure the impact of the zswap/zram compressor (IAA vs. lz4/zstd) on throughput and p99 latency under memory pressure.

Running inside a VM makes **all guest memory anonymous to the host kernel**, so tightening the server cgroup's `memory.max` forces the dataset through compressed swap and compressor speed directly impacts performance. Server VMs are placed in the swept cgroup; client VMs run unconstrained. Networking uses QEMU user-mode (SLIRP), so no bridges or `NET_ADMIN` are required.

# Setting up Environment

Complete the general setup (hardware, kernel, and Python) described in the [README](../../README.md#requirements). The setup script below installs the pinned Python environment for you via `install_dependencies.sh`, so no manual virtual environment is required.

Prerequisites:

* Linux host with KVM (`/dev/kvm`) and QEMU (`qemu-system-x86_64`, `qemu-img`, `qemu-nbd`)
* An ISO tool (`cloud-localds` / `genisoimage`), `ssh`, `numactl`
* zswap or zram configured with a swap backend; IAA hardware + drivers for the IAA profiles
* A host-built `memtier_benchmark` — run [`../redis/setup_redis.sh`](../redis/setup_redis.sh) once

Prepare the VM images once (`setup_vm.sh` runs `install_dependencies.sh`, downloads the Ubuntu cloud image, installs redis + memtier, and generates the SSH keys and dataset). It only needs to run **once**:

```bash
./setup_vm.sh
```

# Methodology

The baseline memory footprint is measured by running the Redis servers inside a host cgroup with unlimited memory. The cgroup `memory.max` is then reduced in steps while monitoring performance regression (throughput, p99 latency), down to the point where regression stays within the threshold. The dataset is the repeated movie dataset (generated by [`repeat_redis_file.py`](repeat_redis_file.py)) chosen for a ~2x-3x compression ratio; `memtier_benchmark` generates a Gaussian 20:80 write:read access pattern.

# Benchmarking Instructions

The benchmark supports **zswap** and **zram** swap modes; the matching host configuration script is called automatically and the HTML report is generated at the end.

```bash
./benchmark.sh                                   # defaults: zswap, 16 server VMs, all compressors
./benchmark.sh --swap-mode zram --server-vms 16  # zram, 16 server VMs
./benchmark.sh --server-vms 2 --instances 3      # 2 servers × 3 instances
```

```
Usage: ./benchmark.sh [options]

  --server-vms <V>          Number of server VMs (client VMs match 1:1) (default: 16)
  --instances <N>           Redis instances per server VM (default: 1)
  --mem-per-instance <GB>   RAM per redis instance; server RAM = N*this (default: 6)
  --swap-mode <mode>        zswap or zram (default: zswap)
  --compressor <name>       Compressor profile or 'all' (default: all)
  --sweep-start <pct>       Sweep start, % of baseline peak (default: 90)
  --sweep-end <pct>         Sweep end,   % of baseline peak (default: 75)
  --sweep-step <pct>        Sweep step in % (default: 5)
  --threshold, -t <pct>     Throughput regression threshold to stop sweep (default: 7)
  --logdir, -l <path>       Output directory (default: ./logdir)
  --help, -h                Show this help
```

Before booting, `benchmark.sh` checks that total VM RAM fits within `host RAM − 10%` and aborts otherwise. Lower `--server-vms`, `--instances`, or `--mem-per-instance` on smaller machines.

# Expected Results

Results are written to `logdir/`: per-scenario `<scenario>.log` files, one `<compressor>.report` summary per compressor, and a combined HTML report showing the memory savings achievable within the performance-regression threshold. The baseline `memory_peak` is the initial memory estimation for the Redis workload. To regenerate the report from existing logs:

```bash
python ../redis/report_plot.py logdir/*/*.report --output-dir logdir
```

# VM-Count Sweep

While `benchmark.sh` sweeps the *memory limit* for a fixed VM count, `vm_sweep_script.sh` sweeps the *number of server VMs* under a **fixed** cgroup memory limit, finding the most server VMs that fit a memory budget before performance drops below the KPI threshold. It generates the `.report` tables and HTML report via `vm_sweep_reporter.py`.

```bash
./vm_sweep_script.sh --swap-mode zram --compressor all
```

```
Usage: ./vm_sweep_script.sh [options]

  --vm-list <points>        Server-VM counts to sweep, ascending (default: swap-mode preset)
  --instances <N>           Redis instances per server VM (default: 1)
  --mem-per-instance <GB>   RAM per redis instance (default: 6)
  --init-limit <GB>         Total physical memory budget (default: 64)
  --zram-limit <GB>         Zram physical mem limit (override for _l in config name)
  --zram-disksize <GB>      Zram virtual disk size (override for _s in config name)
  --swap-mode <mode>        zswap or zram (default: zswap)
  --compressor <name>       Compressor profile or 'all' (default: all)
  --accept-kpi <pct>        Acceptable KPI threshold % (default: 95)
  --threshold, -t <pct>     Throughput drop vs first sweep point that stops the sweep (default: 7)
  --logdir, -l <path>       Output directory (default: ./logdir_vm_sweep)
  --help, -h                Show this help
```

Compressor profiles follow the `<algo>_r<reclaim-batchsize>_p<page-cluster>[_l<zram-mem-GB>_s<zram-disk-GB>]` convention, e.g. `deflate-iaa_r64_p5`, `zstd_r1_p3`, `lz4_r1_p3`, mirroring [`../redis/instance_sweep_script.sh`](../redis/instance_sweep_script.sh).

# Scripts

| Script | Purpose |
|--------|---------|
| `setup_vm.sh` | One-time image setup: cloud image, redis + memtier, SSH keys, dataset |
| `benchmark.sh` | Memory-limit sweep orchestrator (baseline estimation + compression sweep) |
| `vm_sweep_script.sh` | VM-count sweep orchestrator |
| `vm_lib.sh` | VM lifecycle library (start/stop, networking, CPU plan, cloud-init) |
| `vm_ctl.sh` | Utility: start/stop/status/ssh into server or client VMs |
| `report.py` / `vm_sweep_reporter.py` | Log parsers + reporters |
| `repeat_redis_file.py` | Dataset generator (bundled from `tests/redis`) |

The cgroup used is `/sys/fs/cgroup/redisbench_vm`.
